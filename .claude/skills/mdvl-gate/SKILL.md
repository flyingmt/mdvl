# mdvl-gate

CLAUDE.md 규칙 20의 완료 체크리스트를 실행 가능한 형태로 만든 것.

## 쓰는 법

```bash
.claude/skills/mdvl-gate/scripts/gate.sh          # 전부
.claude/skills/mdvl-gate/scripts/gate.sh quick    # 심 B 생략 (반복 중에만)
.claude/skills/mdvl-gate/scripts/gate.sh rust     # Rust만
.claude/skills/mdvl-gate/scripts/gate.sh web      # web만
```

어느 디렉토리에서 실행해도 된다. 스크립트가 자기 위치에서 레포 루트를 계산하고
각 단계를 올바른 디렉토리에 고정한다.

전부 통과할 때만 0을 반환한다. `quick`은 심 B를 안 돌리고도 0을 반환하므로,
**끝났다고 말할 때 쓰면 안 된다** — 스크립트가 마지막 줄에 그렇게 경고한다.

## 순서가 왜 이런가

**web 빌드가 맨 앞이다.** 디버그 빌드의 데몬은 `web/build`를 컴파일 타임에
박아넣는 게 아니라 런타임에 디스크에서 읽는다. 프론트를 고치고 빌드하지 않으면
심 B가 **지난번 자산에 대고** 검증한다 — 통과하지만 아무것도 증명하지 않는다.

**`cargo build --features dev-proxy`가 따로 있다.** 이 feature는 정적 자산
핸들러를 통째로 갈아끼우므로 기본 빌드가 컴파일조차 하지 않는 코드가 있다.
혼자 깨진 적이 있다.

**심 A가 심 B보다 먼저다.** 심 A는 2초, 심 B는 브라우저를 띄운다. 계약이 깨져
있으면 브라우저를 기다릴 이유가 없다.

**clippy는 `-D warnings`다.** 경고를 남겨두면 다음 경고가 묻힌다.

## 두 디렉토리 문제

| 도구 | 어디서 |
|---|---|
| `cargo` (fmt, clippy, build, test) | 레포 루트 |
| `npm`, `npx playwright` | `web/` |

이게 함정인 이유는 셸의 작업 디렉토리가 명령 사이에 유지되기 때문이다. 이
프로젝트에서 실제로:

- 루트에서 `npx playwright test`를 돌려 playwright를 새로 설치하고 설정을 못
  찾아 엉뚱한 에러가 났다
- 루트에서 `npm install`을 돌려 의존성이 잘못된 `package.json`에 들어갔고,
  Node 해석이 상위 디렉토리를 뒤져 로컬에서는 동작해 한동안 안 보였다
- `web/` 기준으로 짠 `rm` 명령이 루트에서 돌아 `README.md`를 지웠다

그래서 스크립트가 위치를 결정하고, 호출자는 위치를 몰라도 된다.

## 실패를 다루는 법

**실패는 실패로 보고한다.** 게이트가 실패했는데 "대체로 통과"라고 말하는 것은
게이트를 없애는 것과 같다. 어느 항목이 왜 실패했는지 그대로 전한다.

**환경 실패와 코드 실패를 구분한다.** 포트 점유, 브라우저 미설치, 네트워크는
코드 문제가 아니다. 섞어서 보고하면 다음 사람이 잘못된 곳을 판다.

**간헐적 실패는 재시도로 덮지 않는다.** 심 B는 실제 데몬과 실제 브라우저를 쓰므로
타이밍에 민감할 수 있다. 재시도해서 통과했다면 **그 사실을 보고한다.** 불안정한
테스트는 없는 테스트보다 나쁘다 — 신호를 준다고 믿게 만들기 때문이다.

## 게이트가 잡지 못하는 것

게이트는 "깨지지 않았다"만 안다. 이것들은 사람이나 다른 에이전트가 봐야 한다:

- 테스트가 **실제로 무는지** — 수정을 되돌려도 통과하는 테스트는 게이트를 통과한다
  (`seam-tester` 담당)
- 문서가 코드와 맞는지 (`contract-keeper` / `verifier` 담당)
- 스펙이 요구한 걸 만들었는지 (`code-review` 스킬)
